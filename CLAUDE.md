# Портфолио Эльвиры Галиевой — контекст для Claude

Читай этот файл первым. Здесь всё, что нужно, чтобы продолжить работу над кейсами портфолио и не сломать уже согласованное.

## 1. Что это за проект

Одностраничный сайт-портфолио Эльвиры Галиевой (дизайн-лид UX/UI, Ида.Лайт). Чистый HTML/CSS/JS, без сборки и фреймворков. Цель: показать сайт карьерному консультанту и работодателям, поэтому качество вёрстки и аккуратность текстов важны.

- Репозиторий: https://github.com/Elvira-dd/portfolio (ветка `main`), опубликован на GitHub Pages: https://elvira-dd.github.io/portfolio/
- Локально (Mac Эльвиры): `~/Desktop/Рабочий стол — 💻Хлебная макушка/Git_portfolio/portfolio` — корень git-репозитория. **Все правки вносить сюда.** Старая папка `.../Хлебная макушка/portfolio` (рядом с `Git_portfolio`) устарела, не использовать.
- История коммитов: `first_commit` → `connect_test` → `second_case_draft`. Коммитить и пушить только по просьбе пользователя.

Файлы в корне репозитория:

- `index.html` — главная: прелоадер, hero, «Кратко», 4 карточки кейсов, опыт, навыки, обучение, контакты.
- `style.css` — **единственная дизайн-система** (токены, типографика, компоненты, анимации появления). Не переписывать без причины.
- `script.js` — настройки (`LINKS`, `IMAGES`, `SKILLS`) и логика: прелоадер, подбор картинок, превью навыков, появление при прокрутке, построчное появление «Кратко», подгонка hero-заголовка по ширине.
- `case-protsessy-komandy.html` — кейс №1 (готов; эталон структуры «акты + вкладки»).
- `case-sajty-dlya-zastrojshhikov.html` — кейс №2 (черновик, есть `??`-заглушки).
- `images/` — `hero.jpg`, `images/case-sites/` (скриншоты `*.webp`, видео `g3-antonovo.mp4` ≈ 23 МБ + постер). Обложки кейсов (`case-process`, `case-sites`, `case-ab`, `case-myolimp`) и логотипы компаний на главной пока не добавлены.
- `fonts/` — CoFo Sans (Regular 400, Medium 500, Bold 700, `.woff`), файлы на месте.
- `.gitignore` — `.DS_Store`, `Claude outputs/`.

**Не коммитить**: папку `Claude outputs/` (расшифровки интервью, резюме — личные данные), `.DS_Store`. Шрифты CoFo Sans платные: убедиться в web-лицензии, раз репозиторий публичный.

## 2. Общий замысел

Каждый кейс — отдельная страница, на главной карточка с кнопкой «кейс →». Ссылка прописывается в `script.js` в объекте `LINKS`.

Кейсы на главной (описания и цифры уже в `index.html`):

1. **Процессы команды** — готов (раздел 5), `LINKS["case-process"]`.
2. **Сайты для застройщиков** — черновик (раздел 6), `LINKS["case-sites"]`. На главной: 60 проектов, 98% удержание (отток 1 из 60).
3. **A/B-тесты и продукт** — страницы нет (`LINKS["case-ab"] = "#"`). На главной: рост конверсии 4–5%, 10–15 клиентов охвачено.
4. **MyOlimp: дизайн с нуля** — страницы нет (`LINKS["case-myolimp"] = "#"`). На главной: −30% запросов от разработчиков, путь до ключевых функций короче на 3 клика.

Исходные материалы (тексты, интервью, структуры) лежат в проекте Claude «Эля» (docs `case_protsessy_komandy_*`). Для кейсов 3–4 материалов в проекте нет — собирать через вопросы пользователю; для кейса 2 тексты Эльвира написала сама.

## 3. Дизайн-система (источник — `style.css`, цвета и размеры брать только оттуда)

Токены: `--black #000`, `--text #111`, `--gray #6B6B6B`, `--gray-label #A8A8A8`, `--placeholder #E5E5E5`, `--row-bg #F9F9F9`, `--tag-bg #F0F0F0`, `--white`; скругления `--r-s 10px`, `--r-m 16px`, `--r-l 20px`.

Сетка **резиновая**: `--max: 100%`, `--gutter: 40px` (32/16 на меньших экранах), контейнер `.wrap`; две колонки «текст + обложка» на главной — `--cols-2: 512fr / 548fr`.

Шрифт: **CoFo Sans** (запасной Inter). Любые размеры/межстрочные брать только из шкалы:

| Класс | Размер | Line-height | Вес | Трекинг |
|---|---|---|---|---|
| `.t-h1` | 73 | 0.97 | 500 | −0.02em |
| `.t-h2` | 32 | 1.2 | 700 | −0.02em |
| `.t-h3` | 22 | 1.05 | 700 | −0.02em |
| `.t-h4` | 18 | 1.35 | 500 | −0.02em |
| body / `.t-big` | 16 | 1.05 | 500 | −0.02em |
| `.t-normal` | 16 | 1.4 | 400 | 0 |
| `.t-small` | 14 | 1.35 | 400 | 0 |
| `.label` | 14 | 1.35 | 700 | −0.01em, **строчными** |

Особенности:
- Базовый сброс в `style.css` — `h1, h2, p { margin: 0 }`. У `h3/h4` сброса нет: обнулять вручную.
- `<button>` не наследует шрифт: нужен `font-family: inherit`.
- Крупные заголовки разделов — `H3 × 1.3`, как `.about__text` на главной.
- Акцентный цвет **только на страницах кейсов** — `--case-accent: #245BF3` (на сайте `--accent` красный, не трогать). Он у стрелок `→` в списках, активной чёрточки бокового прогресса, ссылок «Следующий отдел →», обводки активной вкладки, ключевого визуала, hover у «← портфолио».
- Анимации появления: класс `.reveal` (ставит `script.js` на заголовки, карточки, строки опыта и т.д.; поднимается снизу вверх с задержкой между элементами; учитывает `prefers-reduced-motion`); текст блока «Кратко» появляется построчно (`.about__line`). Класс `.js` на `<html>` выставляет инлайн-скрипт в `<head>` — без JS всё видно сразу.
- Если нужна новая величина — сначала проверить, нет ли подходящего токена. «Своих» размеров и цветов не изобретать.

## 4. Принципы работы с этим пользователем (важно)

- **Общение только по-русски.** Один раз ответила по-английски — пользователь был недоволен.
- **Единая система, сетка, отступы** — главный критерий. Пользователь внимательно смотрит скриншоты и замечает любые расхождения (line-height, отступы, обрыв слов, съезд обводки на 2px). Не «вставляй как получится»: сначала найди, какой существующий класс/токен подходит.
- **Вёрстка по её сетке**: слева заголовок главы (`.side`, 360px), справа текст (`.text`), зазор 120px. Любой новый блок (даже «Моя роль», «Критерии успеха») оформляется как глава в этой сетке, а не отдельной колонкой.
- **Никаких выдуманных мокапов интерфейса.** Всё, что нельзя показать из реальных (конфиденциальных) материалов, — серый блок `.visual-ph` с подписью, что туда нужно добавить. Не рисовать фейковые графики, чаты, таблицы.
- **Тексты**: от первого лица, женский род («выстроила», «предложила»), без канцелярита; логика «наблюдение → гипотеза → решение» подаётся обычным текстом, **без подзаголовков**. Факты и цифры брать только из материалов кейса, ничего не придумывать; если фактов не хватает — спросить.
- Перед правками проверять результат скриншотом (Playwright/Chromium), особенно тонкие вещи (стыки линий, переносы строк, мобильная ширина). Интернет-шрифты в песочнице могут не грузиться — это не баг вёрстки.
- Один актуальный файл на кейс: правки вносить в тот же файл, не плодить копии. Для проверки открывать страницу в обычном браузере (не Quick Look/Preview на Mac — он не подгружает `style.css`).

## 5. Эталон: страница кейса «Процессы команды»

`case-protsessy-komandy.html` подключает `style.css` и дополняет его собственным `<style>` (только новые компоненты, ничего не переопределяя).

Структура страницы:
1. Топбар (← портфолио / имя), hero: `h1.t-h1`, интро, мета (Годы / Сфера = PropTech / Роль), `.visual-ph.hero` (380px).
2. «Контекст» (`.section-grid`, колонка заголовка 360px).
3. **Вкладки актов** — три отдела (дизайн / разработка / продажи): `.tabs-row` на всю ширину сетки, подложка `.tab-plate` с вогнутыми «ушками», плавно переезжает между вкладками; по верху серой панели акцентная линия на всю ширину окна (`.tab-stroke`). Переключение — JS `goto()`, обновляет `--i` на `.tabs-row`.
4. Внутри каждого акта (`.tab-panel`):
   - серая зона `.intro-band`: `act-head` (h2 акта) → **«Зачем переделывать»** (крупный заголовок, `.chapter--major`) → **«Понимание задачи»** (`.intro-list`: потребности пользователя / задачи бизнеса / аудитория) → **«Критерии успеха после запуска»** (`ul.goals`) → **«Моя роль»**;
   - белая зона `.solution`: **«Решение»** → главы (`.chapter` = `.chapter-grid` из `.side h3.t-h3` + `.text`);
   - серая зона **«Что получилось»** (`.results`: число → подпись → график-плейсхолдер) + кнопка «Следующий отдел →».
5. Финал: «Три акта, одна система» (`.final-grid` из трёх колонок).
6. Боковой прогресс `.progress-ticks` (чёрточки по главам активной вкладки, IntersectionObserver); появляется, только когда вкладки дошли до середины экрана; скрыт при ширине < 1300px.

Ключевые компоненты: `.chapter/.chapter-grid/.chapter--major`, `ul.goals` (карточки с `→`, текст 18px при 80% непрозрачности, `<strong>` чёрным), `.visual-ph` (серый плейсхолдер: `<b>` + описание), `.results/.result-item`, `.next-link`, `.stat-note`.

Для нового кейса со структурой «акты» — взять эту страницу как шаблон. Для кейса без актов — как кейс №2 (раздел 6) или единый поток глав.

## 6. Кейс №2: «Сайты для застройщиков» (черновик Эльвиры)

Другая структура — не акты, а один поток секций (`.section-grid`) и блоки клиентов. Топбар, hero, meta, `.goals`, `.final-grid`, `.visual-ph` — те же, что в эталоне.

Секции: hero (2024–2026, PropTech, «UX/UI-дизайнер → дизайн-лид», hero-плейсхолдер «коллаж из экранов») → Контекст (Ида.Лайт: платформа даёт только блоки, остальное на дизайнере; весь веб-дизайн, структура и сторителлинг, общение с клиентом) → «Как я делаю сайт» (`ol.steps`, 5 шагов: структура в Figma, графика, доработка блоков кодом, шаблоны для команды, слежение после запуска) → «Как я понимаю, что получилось» (`ul.goals`) → цифры (`.numbers`: 60 сайтов как UX/UI-дизайнер, 1/60 ушёл, 40 сайтов как дизайн-лид) → **четыре клиента** (`article.site`) → лента «Другие проекты» → «Итог».

Новые компоненты: `.site` (блок клиента, `.site__title`), `.screen/.screen__media` (экран в пропорции 1510×822; `data-href` — открыть живой сайт, `data-gallery` — попап), кнопка «Смотреть» за курсором (`.look`), попап-галерея (`.gallery`, данные в объекте `GALLERIES` в конце файла: картинки или видео+постер), бегущая лента `.more/.marquee` из массива `PROJECTS` (name, url, img 1510×822 в `images/case-sites/more/`).

Клиенты: «Правый берег» (prbereg.ru, `site-1`), «Север» (literaturny.ru, dius-mfk.ru; `site-sever`), g3 — «Антоново» (видео, снятое до публикации) и «Орнамент» (g3.group/complexes/ornament, до переделки; `site-3`), лендинг (yndyc.dev-lite.ru; `site-landing`).
